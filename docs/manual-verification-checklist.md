# Lector AI — Chrome 手动验证清单

> 目的：在真实 Chrome 中加载 `dist/` 扩展后，逐项确认运行时功能是否正常。
> 用法：按顺序执行每一项；在「结果」栏勾选 ✅ / ❌；若 ❌，请粘贴控制台报错（F12 → Console）。

---

## 0. 前置准备（必读）

### 0.1 加载扩展
1. 打开 Chrome，地址栏输入 `chrome://extensions/`
2. 右上角开启 **「开发者模式」**
3. 点击 **「加载已解压的扩展程序」**，选择项目根目录下的 **`dist/`** 文件夹
4. 预期：扩展卡片「Lector AI - Smart Reading Assistant v0.3.0」出现，**无错误徽标**

> ⚠️ 如果卡片上出现红色「错误」按钮，点击它并把错误信息回报 —— 这通常是 `dist` 未构建或 manifest 引用缺失。

### 0.2 后端可用性（关键，决定 AI 功能能否验证）

我已实测默认后端 `https://lector-ai-two.vercel.app/api` 的状态（2026-06-17）：

| 端点 | 线上实测结果 |
|------|-------------|
| `POST /api/summarize` | ❌ `FUNCTION_INVOCATION_FAILED`（500） |
| `POST /api/translate` | ❌ `FUNCTION_INVOCATION_FAILED`（500） |
| `POST /api/chat` | ❌ `NOT_FOUND`（404，路由未部署） |
| `GET /` | ❌ 404 |

**结论：默认后端当前不可用。** 侧边栏聊天 / 摘要 / 翻译 / 解释 / 双语翻译这些 **依赖 AI 的功能** 在默认配置下会失败。要验证它们，请二选一：

- **方案 A（推荐）：自建本地后端。** 在 `api/` 目录部署到本地 Vercel，配好 `OPENROUTER_API_KEY`，然后在扩展里把 `apiBase` 指向本地地址（见 §6）。或
- **方案 B：** 跳过依赖 AI 的功能，只验证 §1、§2、§3、§4、§5、§7 这些**离线功能**（它们不需要后端）。

下文每项都会标注「需后端 ✅/❌」。

## 6. 侧边栏聊天与流式渲染（需后端 ✅ —— §0.2 方案 A）

**前置**：按 §0.2 方案 A 配好本地后端后，把扩展 `apiBase` 指向本地。可用如下方式之一设置：
- 在 DevTools Console（侧边栏页面右键→检查）执行：
  ```js
  chrome.storage.local.set({ apiBase: 'http://localhost:3000/api' })
  ```
  然后关闭重开侧边栏。

| # | 操作 | 预期结果 | 结果 |
|---|------|---------|------|
| 6.1 | 点击扩展图标 或 右下角「L」 | **侧边栏打开**，头部显示当前文章标题 + URL | ☐ |
| 6.2 | 空状态 | 显示「L」logo + 「Chat with this page」+ 4 个建议按钮（总结全文/关键观点/解释难点/继续追问） | ☐ |
| 6.3 | 点建议按钮或输入问题回车 | 出现用户消息气泡（右，蓝紫渐变）+ 助手气泡（左，白底）显示「thinking…」转圈 | ☐ |
| 6.4 | **流式渲染** | 助手气泡内容**逐字增长**（SSE token 流式），滚动条自动下滚 | ☐ |
| 6.5 | 文本含 Markdown（标题/列表/代码） | 正确渲染为 HTML（加粗、列表、代码块） | ☐ |
| 6.6 | 回答含 `[0]` 引用标记 | 渲染为可点击的上标引用芯片（如 `[0]`） | ☐ |
| 6.7 | 点击引用芯片 | 页面滚动到对应段落，段落高亮脉冲（`lector-pulse`）2 秒 | ☐ |
| 6.8 | 底部出现「X free left today」 | 非登录免费用户显示剩余次数（dev 后端无 Supabase 时可能不显示） | ☐ |
| 6.9 | 后端返回 429（超额） | 助手气泡显示「⏸️ Daily free limit reached...」 | ☐ |
